# 使用场景示例

## 场景1：股票买卖点分析

### 用户问题
"请分析 sz000001（平安银行）的日线级别买卖点"

### 分析思路

1. **明确级别**：日线级别
2. **获取数据**：获取足够的日线K线数据
3. **分析结构**：识别当前趋势和中枢
4. **判断买卖点**：检查是否有买卖点信号
5. **评估风险**：给出止损位和目标位

### 示例输出

```
## sz000001 日线级别分析

### 当前结构
- 当前处于下跌趋势
- 最近一个中枢区间：[12.50, 13.20]
- 当前价格：11.80

### 买卖点信号
- ✅ 出现一买信号
- 信号时间：2024-06-14
- 信号价格：11.80

### 背驰确认
- MACD背驰：是
- 价格创新低：11.80 < 前低12.00
- MACD柱面积：当前0.8 < 前段1.2

### 操作建议
- 买入区间：11.80 - 12.00
- 止损位：11.50（跌破前低）
- 目标位：13.20（中枢上沿）
- 风险收益比：1:4

### 完全分类
1. **情况A**：反弹进入中枢
   - 应对：持有，目标13.20
2. **情况B**：反弹不进入中枢
   - 应对：减仓，等待三卖
3. **情况C**：继续下跌
   - 应对：止损11.50
```

## 场景5：背驰检测

### 用户问题
"请检测 sh600000（浦发银行）的背驰情况"

### 分析思路

1. **获取数据**：足够的K线数据
2. **计算指标**：MACD等技术指标
3. **识别背驰**：检查是否有背驰信号
4. **确认信号**：多指标确认

### 示例输出

```
## sh600000 背驰检测

### 检测参数
- 周期：日线
- 时间范围：2024年1月-6月
- 指标：MACD（12,26,9）

### 背驰信号
- ✅ MACD背驰：按核心库返回值记录
- ℹ️ 斜率背驰：按核心库返回值记录，不预设为“是”
- ℹ️ 测度背驰：按核心库返回值记录，不预设为“待确认”
- 组合判据：全量 / 任意 / 任选 / 配置 / 模式分别列出

### 详细分析
1. **原子判据**：MACD、斜率、测度分别记录 True/False/不可用。
2. **组合判据**：全量、任意、任选、配置和模式单独记录。
3. **证据等级**：根据独立原子证据数量和聚合确认结果计算强/中/弱。
4. **结构约束**：背驰只是买卖点辅助证据，不能单独生成一买或一卖。

### 操作建议
- 仅当结构模板同时成立时，才输出 T1/T1P 候选
- 等待后续 K 线确认，不把背驰本身当作可执行信号
- 止损使用核心买卖点 factory 的破位值、失效 K 线和有效性
```

## 注意事项

1. **数据质量**：确保数据完整、准确
2. **级别明确**：任何分析都要先明确级别
3. **风险控制**：任何策略都要包含止损
4. **完全分类**：列出所有可能情况
5. **纪律执行**：严格按照系统操作
6. **避免情绪化**：客观分析，机械操作

## 场景6：止损体系（v3.1.0 factory 字段）

### 用户问题
"请分析 sz000001 当前一买的止损位是否合理"

### 分析思路

1. **取官方字段**：用 `买卖点.T1买点` factory 构造对象，取 `破位值` / `有效性` / `失效K线`
2. **不要自己近似**：项目早期 `signal["break"]` 只是端点近似，factory 给出的才是带历史回测的失效判定
3. **多字段交叉**：MACD 柱匹配 / 柱分型匹配 给信号可靠性评分

### 示例输出

```
## sz000001 一买止损分析

### 当前信号
- 类型：T1买（趋势背驰，≥2 同向中枢）
- 时间：2024-02-17
- 价格区间：[15.37, ...]

### 止损字段（factory 构造）
| 字段 | 值 | 含义 |
|---|---|---|
| 破位值 | 15.37 | 跌破即失效的边界 |
| 有效性 | False | factory 已判定此信号失效（被后续 K 线突破） |
| 失效偏移 | -1 | 距失效点的 K 线根数（-1 = 紧邻） |
| 与MACD柱子匹配 | True | 买在 MACD 负柱，符合官方约定 |
| 与MACD柱子分型匹配 | True | MACD 柱分型与买卖点分型匹配（严格） |
| 失效K线 | K#230 | 具体失效 K 线 |

### 风险解读
- 此 T1买 **已被突破失效**（有效性=False），不应按当前信号入场
- 若已持仓，按 失效K线 后一根退出
- MACD 双匹配 + 严格分型匹配 = 信号可靠性高，但走势已演变为二类机会或反向
```

### 关键调用
```python
from chanlun import 买卖点
bp = 买卖点.T1买点(分型, 当前K线, "auto", "", 破位值)
print(bp.有效性, bp.失效K线, bp.与MACD柱子分型匹配)
```

## 场景7：跨周期共振（v3.1.0）

### 用户问题
"日线和周线同时出现买点，是不是强信号？"

### 分析思路

1. **多周期数据**：eltdx 自动拉 `day + week`；CSV 多文件需手工拼
2. **同向匹配**：主周期（小）的每个信号在 30 天时间窗内查其他周期同向信号
3. **强度评分**：参与共振的周期数（2 = 弱共振，3+ = 强共振）

### 示例输出

```
## sz000001 跨周期共振

### 共振事件（共 3 个，强度≥2）
| 主时间 | 方向 | 强度 | 参与周期 |
|---|---|---|---|
| 2024-03-22 | 买 | 3 | day/week/month 均为 T1买 |
| 2024-05-03 | 卖 | 3 | day/week/month 均为 T3B卖 |
| 2024-06-28 | 卖 | 3 | day/week/month 均为 T2卖 |

### 解读
- 2024-03-22 三周期同买 = **强共振买点**（大级别同向确认）
- 注意：此场景用同一份数据喂给三个周期仅用于验证逻辑；
        实战中需保证各周期数据真实对应关系（eltdx 自动取数）
```

### 关键调用
```python
from chanlun import 立体分析器, K线
# 多周期分别投喂（CSV/eltdx）
engine = 立体分析器("sz000001", [86400, 604800, 2592000], config)

obs_week = engine._单体分析器[604800]
obs_month = engine._单体分析器[2592000]
# 各周期 增加原始K线 ...（详见 chan_analyzer.py）
# analyze() 末尾自动汇总 跨周期共振 列表
```

## 场景8：多级别展开（v3.1.0）

### 用户问题
"扩展级别到底有几层？每层结构如何？"

### 分析思路

1. **看序列组**：`扩展线段序列组 = [n₁, n₂, n₃]` 是每层的线段计数
2. **逐层展开**：取 `detail["多级别展开"]` 看每层明细
3. **联立分析**：跨层找「线段之线段」「中枢之中枢」，识别级别递归

### 示例输出

```
## sz000001 多级别展开（day 周期）

### 扩展线段层
| 层级 | 数量 | 含义 |
|---|---|---|
| L1 | 10 | 基础扩展线段 |
| L2 | 3 | 扩展线段之扩展线段（次级递归） |
| L3 | 1 | 第三层递归 |

### L2 明细（次级递归）
- 线段#11 向上 [11.20 ~ 12.50] 2024-04-15 → 2024-05-20
- 线段#12 向下 [10.80 ~ 12.00] 2024-05-21 → 2024-06-10
- 线段#13 向上 [11.50 ~ 13.00] 2024-06-11 → 2024-07-05

### 操作含义
- L2 是 L1 之上的递归结构，承载「线段级别」的中长线判断
- L3 出现意味着走势在更高级别形成独立结构（强趋势信号）
- 多级别联立：L1 买卖点 + L2 同向 = 强化信号；反向 = 警惕反转
```

### 关键字段
```json
{
  "多级别展开": {
    "扩展线段层": [
      {"层级": 1, "数量": 10, "线段": [...]},
      {"层级": 2, "数量": 3, "线段": [...]},
      {"层级": 3, "数量": 1, "线段": [...]}
    ],
    "扩展中枢层": [
      {"层级": 1, "数量": 3, "中枢": [...]}
    ]
  }
}
```

## 场景9：参数杠杆实战（v3.1.0 CLI）

### 用户问题
"成笔太稀疏/太密集了，怎么调？"

### 分析思路

1. **`--笔内元素数量`**：最强杠杆，3 ↔ 5 可让笔数 ×2.9
2. **`--指标计算方式 高/低`**：MACD 数值变化导致买卖意义命中数 ±20%
3. **`--买卖点_指标匹配_MACD False`**：放宽严格性，信号数明显增多

### 示例对比

```bash
# 默认
python chan_analyzer.py --source csv --input test_data.csv --symbol 000001 --freq day --json
# → 笔=6, 买卖点=1

# 改笔内元素数量
python chan_analyzer.py --source csv --input test_data.csv --symbol 000001 --freq day --笔内元素数量 3 --json
# → 笔=18, 买卖点=4

# 改指标计算方式
python chan_analyzer.py --source csv --input test_data.csv --symbol 000001 --freq day --指标计算方式 高 --json
# → MACD 数值变化，买卖意义命中数 ±3

# 放宽 MACD 匹配
python chan_analyzer.py --source csv --input test_data.csv --symbol 000001 --freq day --买卖点_指标匹配_MACD False --json
# → 信号数翻倍（不再要求 MACD 严格匹配）
```

### 选择建议
- **初筛**：默认 + 激进识别 + MACD False → 信号多而杂
- **二筛**：默认 + 严格 MACD → 信号少而精
- **复盘**：`--笔内元素数量 3` 看更细结构，与默认对比找关键转折
