# 缠论分析技能

## 职责边界

本 Skill 的默认任务是**解释缠论结构**，不是预测行情、荐股或替用户决定仓位。分析结果必须区分：

- **事实**：核心库或输入数据直接给出的结构、价格、时间和指标值。
- **推断**：基于结构规则得到的走势、背驰或买卖点候选。
- **策略**：仅由 AI 在用户明确请求时生成的条件化预案，必须包含确认条件、失效条件及用户风险约束。

脚本默认只输出当前结构、理论候选和信号状态，不生成策略计划、行动建议或仓位结论。

## 定义标准与实现口径

缠论概念的规范定义以 [缠论核心理论](references/chan-theory-core.md) 为主，包括分型、笔、线段、中枢、走势类型、买卖点、背驰和级别理论。主 Skill、示例和代码注释不得另行发明或覆盖这些定义。

需要区分两类信息：

- **理论定义**：按核心理论文件解释“是什么、成立条件是什么”。
- **实现口径**：按 Rust 核心库和本 Skill 说明“当前程序如何计算、输出或近似”。

如果理论定义、核心库行为和 Skill 分类不一致，必须分别标注差异；实现结果只能称为“核心库结果”或“Skill 候选”，不能反向当作缠论定义。

特别是：日线、30 分钟、5 分钟等首先是**时间周期**，不自动等同于缠论的高级别、次级别或级别递归。严格的级别递归以结构序列组和核心理论定义为准。

## 默认分析流程

按以下顺序读取分析结果：

1. **数据范围**：标的、时间周期、时间范围、复权方式和数据质量。
2. **周期背景**：若输入包含多个时间周期，先看较大时间周期的方向，再看当前分析周期；不要直接把时间周期名称当作缠论递归级别。
3. **当前结构**：走势类型、当前线段、当前中枢及关键区间。
4. **背驰证据**：说明命中的具体判据，不只写“有背驰”。
5. **买卖点候选**：区分结构分类、结构失效条件和确认状态。
6. **条件化结论**：给出等待条件、失效条件和仍需验证的内容。

未确认的结构不得写成已确认信号；历史批量分析不得使用未来 K 线回填确认；不得承诺收益或必然涨跌。

## 核心规则

- 任何结论都必须注明是时间周期还是缠论结构级别。不同时间周期的结构不能直接混为一个买卖点。
- 买卖点先看结构，再看背驰和指标。背驰本身不能单独升级为一买/一卖。
- 一类结构使用线段内部的笔中枢：趋势候选为 `a+A+b+B+c`，盘整候选为 `a+A+b`。
- `obs.笔_中枢序列` 是底层审计视图；买卖点分类默认使用每条线段的 `seg.合_中枢序列`。
- 方向由结构终点判断：向上笔终点为顶分型时是卖出语境，向下笔终点为底分型时是买入语境。
- 买卖点候选由笔、线段内部中枢、第三买卖线和背驰结构分类；不调用 Rust 买卖意义、指标匹配或买卖点 factory。
- 结构失效必须由缠论结构规则或显式上游状态单独证明。脚本输出结构失效边界与条件，但在规则未完整形式化时不自动把候选改为已失效。

## 核心库硬约束

生产路径使用 `chanlun` 的 Rust/PyO3 绑定和 `scripts/chan_analyzer.py`，不要把 `chanlun.chan` 的兼容实现与 Rust 对象混用。

- 分析器对 `data_by_period` 中每个实际输入周期单独构造 `观察者`，再调用 `增加原始K线`；不要把某一周期的 K 线冒充其他周期，也不要在该批量分析路径调用 `立体分析器` 自动合成。
- 只有显式需要从小周期实时合成大周期时才使用核心库的 `立体分析器` 和 `投喂K线`；周期列表、pending 行为及其异常边界仅适用于该实时合成路径。
- `PanicException` 继承 `BaseException`，边界兜底不能只捕获 `Exception`。
- 观察者构造参数为标的、周期秒数和配置；每个周期使用独立配置副本。
- 周期名支持 `1m/5m/15m/30m/60m/day/week/month`，周期秒数转换见 `data_source.py`。

这些约束只用于避免运行时错误；不要在普通分析回答中展开 Rust API 细节。

## 默认输出

优先使用脚本输出中的 `语义摘要` 和当前状态，按以下结构简洁回答：

```text
数据质量：可用性、周期、时间范围、复权方式
当前结构：走势类型、方向、当前线段、中枢区间
背驰证据：命中的判据及证据强弱
信号候选：类型、方向、时间、确认状态、核心依据
结论：当前应等待什么，什么情况使判断失效
```

只有用户明确要求审计、复核或程序消费时，才展开原始序列、字段来源、证据矩阵和状态轨迹。

## AI 策略与仓位管理

当且仅当用户明确要求策略、交易预案或仓位管理时，AI 才能在结构分析结果之上生成条件化建议。建议必须引用已输出的结构事实、理论候选、确认状态和结构失效边界，并先取得或声明以下缺失条件：操作时间周期、当前持仓与成本、可承受单笔亏损、总风险预算和交易限制。

策略建议只能描述“满足什么条件后如何重新评估”，不能把候选信号写成必须执行的买卖指令；不得给出保证收益、固定目标价或脱离用户风险预算的仓位比例。

## 按需增强

先完成默认结构分析，再按用户问题加载对应能力：

| 用户需求 | 展开内容 |
|---|---|
| 多周期联立 | `input_periods`、较大时间周期背景和共振；说明这不是 Rust 自动递归 |
| 指标确认 | MACD、RSI、KDJ、BOLL/均线；指标只能作为辅助证据 |
| 买卖点细分 | 一/二/三类及 T1/T1P/T2/T2S/T3A/T3B 分类规则 |
| 结构失效复核 | 结构失效边界、失效条件和状态轨迹；不使用 Rust 交易信号 |
| 策略与仓位管理 | AI 根据结构结果和用户风险约束生成条件化预案；脚本不生成策略计划或执行结论 |
| 数据源与工程诊断 | eltdx 分页、复权、依赖检查、Rust 绑定兼容性 |
| 回归或实现审计 | 原始 JSON、信号 schema、状态轨迹和测试脚本 |

## 运行入口

唯一分析入口是 `scripts/chan_analyzer.py`。离线 CSV 优先用于可复现分析：

```bash
python scripts/chan_analyzer.py --source csv \
  --input tests/fixtures/test_data.csv --symbol 000001 --freq day --json
```

CSV `date` 字段支持 ISO 时间与时区偏移；带时区时间会归一化为 UTC，未带时区的日期/时间按 UTC 解释。纯日期作为 UTC 日历日期标签使用，避免依赖运行机器的本地时区。

在线 `eltdx` 取数只在用户明确需要实时或指定数据源时使用。首次运行或切换环境时检查依赖：

```bash
python scripts/check_dependencies.py --json
```

脚本、依赖、回归测试和完整字段说明见 `scripts/`；不要把这些工程细节当作默认分析步骤。
