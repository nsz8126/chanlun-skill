# 缠论分析技能

## 概述

本技能基于 `chanlun` 库（缠论分析引擎，MIT 许可，YuYuKunKun）提供 A 股市场的缠论分析能力。可选搭配 `eltdx`（通达信协议数据源）在线取数。

**核心架构**：chanlun 核心库产出结构化缠论数据 → AI 验证分析 → 生成报告

> 关键事实：`chanlun` 是**纯 Python** 实现（`chan.py` 为完整源码，`__init__.pyi` 为类型提示），API 面两者一致。本技能直接调用核心库，不做二次封装。

## 三大核心理念

1. **不测而测** —— 不预测市场未来，只分析当下正在发生什么
2. **完全分类** —— 事先列出所有可能情况，为每种情况准备应对策略
3. **级别思维** —— 任何分析都必须明确级别，不同级别有不同操作策略

## 操作原则

- **生存第一**：永远不要让一次失败毁掉所有
- **机械操作**：严格按系统操作，不加入个人情绪
- **节奏把握**：识别底、顶及中间过程，分阶段采取不同策略

## 核心库能力速查（务必对照使用）

### 立体分析器（多周期）

```python
from chanlun import 立体分析器, 缠论配置, K线

config = 缠论配置.不推送()          # 静默配置，不推送
engine = 立体分析器("sz000001", [86400, 604800], config)   # 周期组长度必须 ≥2

# 批量分析（本脚本实际采用）：分别对每个周期的观察者直接投喂，无 pending
obs_day = engine._单体分析器[86400]
obs_day.增加原始K线(K线.创建普K("sz000001", ts, o, h, l, c, v, i, 86400))

# 实时流式（可选，勿用于批量）：只投喂最小周期，引擎自动合成更大周期，
# 但最后一根 K 线会留在 pending 状态不进序列（需下一根触发 flush）
engine.投喂K线(K线.创建普K("sz000001", ts, o, h, l, c, v, i, 86400))
```

**必须遵守的硬约束：**

1. **周期组长度 ≥ 2**。单周期（如 `[86400]`）会让引擎抛出 `PanicException`（`index out of bounds`）。该异常继承 `BaseException`，**普通 `except Exception` 抓不到**，脚本会无声崩溃。
2. **批量分析用 `观察者.增加原始K线`，不要用 `投喂K线`**。`投喂K线` 是增量式合成器（实时流式场景），会遗留最后一根 pending；且若声明 `[1800, 86400]` 却投喂 86400s 的 K 线会抛 `PanicException: 周期不匹配`。批量分析直接对各周期观察者分别 `增加原始K线` 即可。
3. **周期秒数对照**：60(1m)/300(5m)/900(15m)/1800(30m)/3600(60m)/86400(day)/604800(week)/2592000(month)。
4. **month 是最大周期，无法向上补足**。单独分析 month 时，周期组用 `[604800, 2592000]`（week 作占位留空）。用 `增加原始K线` 直接投喂无此问题；若用 `投喂K线` 则须注意它会校验周期==周期组最小值。**注意 `观察者.投喂原始数据` 需要 5 个位置参数（开高低收量），投单根 K 线要用 `增加原始K线`。**
5. **`周期组` 是属性不是方法**（`engine.周期组` 直接返回 list，调用 `周期组()` 抛 `TypeError`）。`立体分析器` 公开面只有 `周期组`/`投喂K线`/`测试_保存数据` 三个成员，**没有公开取观察者的方法**，取观察者只能走私有字段 `engine._单体分析器[秒数]`。

### 观察者（结构序列）

每个周期的 `观察者` 暴露 22 个结构序列，全部是只读属性：

| 属性 | 含义 |
|---|---|
| `普通K线序列` / `缠论K线序列` / `基础缠K序列` | K 线 |
| `分型序列` | 分型 |
| `笔序列` / `笔_中枢序列` | 笔、笔中枢 |
| `线段序列` / `中枢序列` | 线段、线段中枢 |
| `扩展线段序列` / `扩展中枢序列` | 扩展线段、扩展中枢 |
| `扩展线段序列_线段` / `扩展中枢序列_线段` | 线段级扩展 |
| `线段_线段序列` / `线段_中枢序列` | 线段之线段 |
| `扩展线段序列_扩展线段` / `扩展中枢序列_扩展线段` | 扩展线段之扩展线段 |
| `线段序列组` / `中枢序列组` / `扩展线段序列组` / `扩展中枢序列组` / `混合扩展线段序列组` / `混合扩展中枢序列组` | 按层次分组的序列组（多级别递归结构） |

### 对象字段（取数直接读这些，不要二次推断）

- **笔/线段（`虚线`）**：`.高` `.低` `.方向` `.序号` `.级别` `.文`(起点分型) `.武`(终点分型) `.获取数据文本()` `.图表标题`
- **分型**：`.时间戳` `.分型特征值` `.结构`(顶/底) `.左/.中/.右`
- **中枢**：`.高` `.低` `.高高` `.低低` `.第三买卖线` `.当前状态()` `.完整性(虚实)` `.获取数据文本()`
- **缠论K线**：`.高` `.低` `.分型` `.分型特征值` `.买卖点信息` `.标的K线`

> 注意：`分型.时间戳` 与 `分型.中.标的K线.时间戳` 不是同一个值；`中枢.完整性()` 的参数是字符串 `"实"/"虚"/"合"`，不是布尔。

### 买卖点

**`虚线.买卖意义(线, 观察者) -> (bool, str)`** 是核心的买卖点判据，但语义要分清：

- 只返回「此处是否具备买卖意义」和理由（如 `"背驰过:0,极值:True,柱子分型匹配"`）
- **不返回买/卖方向，不返回买卖点类型**
- **方向判定**：向上笔终点是顶分型 → 卖出语境；向下笔终点是底分型 → 买入语境
- 配置注释 `买卖点_指标匹配_MACD: bool = True  # 买在负，卖在正！` 是官方判据：MACD 柱为负是买点、为正对应卖点

**`买卖点类型` 枚举共 18 种**：`一买/一卖/二买/二卖/三买/三卖` + 12 种 T 系列（`T1买`…`T3B卖`），均带 `是买点`/`是卖点` 布尔属性。

**`买卖点` 工厂方法**（可生成带止损信息的完整买卖点对象）：`买卖点.一买点(分型, 当前K线, 标识, 备注, 中枢破位值)`，返回对象含 `.破位值` `.失效K线` `.有效性` `.与MACD柱子匹配`。

### 背驰

`背驰分析` 共 14 个方法，`线段`/`笔` 另有深度方法。**全部是 classmethod，实例必须作为第一个参数传入**：

```python
from chanlun import 背驰分析, 线段

线段.判断线段内部是否背驰(段, 观察者)      # 正确
# 段.判断线段内部是否背驰(观察者)           # 错误：会抛 AttributeError

背驰分析.MACD背驰_OBS(进段, 出段, 观察者)   # MACD 背驰
背驰分析.斜率背驰(进段, 出段)               # 斜率背驰
背驰分析.测度背驰(进段, 出段)               # 测度背驰
背驰分析.全量背驰_OBS(进段, 出段, 观察者)    # 全量（MACD+斜率+测度）
线段.是否背驰过(段, 观察者)                 # 返回背驰过的缠K列表
```

### 技术指标（挂载在每根 K 线上）

指标**不是**由 `观察者` 单独返回，而是挂在每根 K 线上：

```python
k.macd   # 平滑异同移动平均线：.DIF .DEA .MACD柱 .快线EMA .慢线EMA
k.rsi    # 相对强弱指数：.RSI .平均上涨 .平均下跌
k.kdj    # 随机指标：.K .D .J .RSV
k.指标   # 指标容器（可含 BOLL 等）
```

另有 `K线.获取MACD(序列, 始, 终) -> {'阴','阳','总','合'}`，正是量化背驰所需的面积量。

### 缠论配置（74 个字段）

`缠论配置(**kwargs)`，字段名即中文参数名。常用杠杆：

| 字段 | 默认 | 说明 |
|---|---|---|
| `笔内元素数量` | 5 | 成笔最低长度，改 3 笔数可 ×2.9 |
| `买卖点激进识别` | False | 激进模式不考虑分型完整性 |
| `买卖点偏移` | 1 | 买卖点最大偏移 |
| `买卖点_指标匹配_MACD` | True | 买在负、卖在正 |
| `线段内部背驰_MACD/斜率/测度` | True | 内部背驰开关 |
| `计算指标` | True | 是否计算 MACD/RSI/KDJ |
| `MACD_参数列表` / `RSI_周期列表` / `KDJ_参数列表` | None | 多参数指标 |

`config.不推送()` 生成静默配置；`config.to_dict()` 序列化。

## 分析思维流程

1. **明确级别**：周线/日线/30m/5m？操作级别是什么？
2. **识别结构**：上涨/下跌/盘整？中枢在哪？当前位置？
3. **判断买卖点**：第几类买卖点？有无背驰确认？
4. **评估风险收益**：止损位（`破位值`）、目标位（中枢上下沿）
5. **完全分类**：列出所有可能情形及应对策略

## 数据与表达纪律

1. **先确认数据**：明确标的、时间范围、周期、复权、数据源。缺数据先说明限制，不编造。
2. **区分事实与判断**：先列可观察的结构（K线/分型/笔/线段/中枢/指标），再给缠论解释；标注不确定性。
3. **避免确定性荐股**：输出教育性分析和条件化预案，不承诺收益。
4. **风险优先**：任何策略包含失效条件、止损/退出、仓位约束、等待方案。
5. **当前行情要验证**：涉及实时行情必须核验数据后再分析。

## 脚本工具

### chan_analyzer.py（唯一分析入口）

直接基于 chanlun 核心库，自包含、无额外封装依赖。

```bash
# 本地 CSV 分析（离线可复现，推荐）
python scripts/chan_analyzer.py \
    --source csv --input scripts/test_data.csv --symbol 000001 --freq day

# 中文周期名等价
python scripts/chan_analyzer.py \
    --source csv --input scripts/test_data.csv --symbol 000001 --freq 日线

# 结构化 JSON 输出（便于 AI 消费）
python scripts/chan_analyzer.py \
    --source csv --input scripts/test_data.csv --symbol 000001 --freq day --json

# 在线数据（eltdx 3.x，通达信 7709 协议，需网络连通）
python scripts/chan_analyzer.py \
    --source eltdx --code sh600519 --freq day --count 800

# 输出到文件
python scripts/chan_analyzer.py \
    --source csv --input scripts/test_data.csv --symbol 000001 --freq day --output report.txt
```

> eltdx 模式 `--code` 即标的（如 sh600519 / sz000001 / 000001），分析标题自动用 code；`--symbol` 可覆盖。周期 `--freq` 支持 1m/5m/15m/30m/60m/day/week/month。

**脚本输出内容**（每个周期）：
- 结构计数：K线/缠K/分型/笔/笔中枢/线段/中枢/扩展线段/扩展中枢/线段_线段/扩展线段_扩展线段
- 级别递归序列组（线段序列组/中枢序列组/扩展序列组/混合扩展序列组 逐层计数）
- 最近笔（序号/方向/端点时间/高低价）
- 笔中枢（区间/极值/当前状态）
- **T 系列买卖点**（六类 = 走势类型 + 背驰信息对基础买卖点的精确化，含破位值/止损参考）
- 背驰（`线段内部背驰` + `笔内背驰` + 相邻线段对 MACD/斜率/测度/全量）
- MACD 柱面积量（`K线.获取MACD` 全序列 阳/阴/合/总）
- 最近 3 根 K 线技术指标（MACD/RSI/KDJ + 可选 BOLL/均线）

**T 系列买卖点判据**（在 6 类基础买卖点之上二次细分）：

| 类型 | 基础 | 细分判据 |
|---|---|---|
| T1 / T1P | 一类（背驰点） | 趋势背驰（≥2 同向中枢）= T1；盘整背驰（0~1 中枢）= T1P |
| T2 / T2S | 二类（有买卖意义、非背驰） | 一类之后第一次回踩不破 = T2；后续回踩不破 = T2S |
| T3A / T3B | 三类（`中枢.第三买卖线` 非空） | 中枢在一类之后 = T3A（新中枢突破）；在一类之前 = T3B（老中枢突破，即二三类重合） |

**每个信号附带的止损字段**（`止损` 子对象，由 `买卖点` factory 构造）：

| 字段 | 含义 |
|---|---|
| `破位值` | 工厂根据输入计算的失效边界（中枢沿/端点近似） |
| `失效K线` | factory 判定的失效 K 线（若有） |
| `有效性` | factory 判定当前是否仍有效（已被突破则 False） |
| `失效偏移` | 距失效的 K 线根数 |
| `与MACD柱子匹配` | factory 判定的 MACD 柱正负是否匹配（买在负/卖在正） |
| `与MACD柱子分型匹配` | MACD 柱分型是否与买卖点分型匹配（更严格） |

factory 命名规则：`信号.kind + "点"` 直接命中 18 个 classmethod（如 `T1买` → `买卖点.T1买点`）。

**跨周期共振**（`result["跨周期共振"]`，需多周期数据）：
- 主周期（小）的每个信号，在 30 天时间窗口内查找其他周期的同向信号
- 至少 2 个周期同向才算共振事件，强度 = 参与周期数
- 输出含 `primary_time` / `direction` / `strength` / `matches`（含距离天数）

**多级别展开**（`detail["多级别展开"]`，审计 Stage 3-13）：
- 把 `扩展线段序列组=[n₁,n₂,n₃]` 逐层展开为 L1/L2/L3
- 每层含层级、数量、明细（序号/方向/端点/起讫时间）
- 这是缠论「级别递归」的载体，多级别联立分析的基础

**可选参数**（配置杠杆）：
```bash
--笔内元素数量 3              # 成笔最低K线数（默认5，改3笔数约×2.9）
--买卖点激进识别              # 不考虑分型完整性
--boll                       # 计算布林带
--均线 5,20,60               # 计算均线
--均线类型 SMA,EMA           # 均线类型（默认 SMA，可多类型）
--指标计算方式 高              # 指标计算基准：收/高/低（影响 MACD 数值与买卖意义命中数）
--买卖点_指标模式 全量         # 买卖点指标匹配：全量/任意/配置
--买卖点_指标匹配_MACD True   # 是否要求买卖点与 MACD 柱分型匹配（True=严格）
```

**关键设计**：
- `--freq` 自动补上级周期（如 `day` → `[day, week]`，eltdx 分别取各周期真实数据），规避单周期 panic
- 数据加载后**直接对观察者 `增加原始K线` 批量投喂**，不走 `立体分析器.投喂K线` 的增量式合成器（那会遗留「最后一根 pending 不进序列」，且是实时流式场景才需要的设计）
- 周期名支持中英文（1m/5m/…/day/week/month ↔ 1分钟/日线/周线/月线）
- 取数全部走核心库原生字段（`.高/.低/.分型特征值`），不做二次推断
- 三买卖点用核心库已算好的 `中枢.第三买卖线`；一/二类用 `买卖意义` 的「背驰」判据；T 系列细分用「数同向中枢」「一类后回踩次序」「中枢时序」。严格缠论的一二类需多级别递归，本输出作为初筛而非最终结论。
- 止损字段走官方 `买卖点` factory（`缠论K线.买卖点信息` 在所有配置下实测返回空 set()，故不可用）
- 异常处理全程用 `except BaseException` 兜底 Rust `PanicException`（继承 BaseException，普通 `except Exception` 抓不到）

> 脚本只用于复现结构计算和整理输入数据，不能替代对级别、数据质量和交易风险的判断。`eltdx` 官方仅授权个人学习与非商业研究使用。

**运行环境**：Python >= 3.11，`pip install chanlun eltdx`（`requirements.txt` 已声明）。

**灰度测试**：47 个用例覆盖 12 个 PART（功能/边界/数据/方向/T 系列/趋势/T3A-B/止损/多级别/共振/CLI 杠杆/性能）。`python gray_test.py` 退出码 0 = 全部通过。
