# 项目分析技能

## 目标

该技能用于快速理解一个代码仓库的真实状态：它解决什么问题、如何组织、关键入口在哪里、依赖和运行方式是什么、是否具备可维护性和可验证性，以及在修改前需要注意哪些风险。

适用于：
- 熟悉新代码库
- 评估项目健康度与可维护性
- 准备重构、接手维护或扩大功能前的分析
- 诊断“为什么这个项目这么做”与“哪些部分最关键”

## 工作流

### 1. 先看项目“是什么”

先回答以下问题：
- 这个仓库的主要目标是什么？
- 用什么语言、框架和运行方式？
- 是 library、CLI、服务端、脚本工具、还是混合型项目？

优先阅读：
- README.md
- 根目录说明文档
- package.json / pyproject.toml / Cargo.toml / go.mod / pom.xml 等清单文件
- 关键目录结构

输出要点：
- 项目定位
- 受众和使用场景
- 最核心的模块和交付物

### 2. 识别结构与入口

建立“仓库地图”：
- 哪些目录是源代码、测试、脚本、配置、文档？
- 哪个文件是主入口 / 启动入口 / 命令入口？
- 哪些模块是核心业务逻辑、哪些是基础设施或适配层？

优先检查：
- src/、app/、lib/、services/、scripts/、tests/
- main/startup/bootstrap 文件
- 依赖注入、路由、配置加载、数据库/模型定义等横切层

输出要点：
- 架构概览
- 关键调用链
- 模块职责边界

### 3. 追踪运行与验证方法

确认项目如何真正运行，而不是仅凭目录猜测：
- 安装命令是什么？
- 启动命令是什么？
- 测试命令是什么？
- 是否有 lint、format、typecheck、build、coverage 等流程？

优先检查：
- CI 配置
- Makefile / justfile / taskfile / package scripts
- 测试目录与命名规则
- 依赖安装和环境要求

输出要点：
- 典型运行步骤
- 代码的最小验证路径
- 是否存在缺失的自动化检查

### 4. 评估实现与风险

在理解结构后，判断项目的现实状态：
- 代码是否清晰分层？
- 是否存在隐藏耦合、重复逻辑或过度抽象？
- 关键模块是否有明确边界和测试覆盖？
- 是否依赖不可控的外部系统、协议或数据源？
- 是否存在已知缺陷、设计折中或不完整的功能？

检查重点：
- 关键业务流是否可追踪
- 是否存在“只读配置/动态加载/全局状态”导致的隐患
- 是否有“功能实现但缺少验证”的地方
- 是否大量依赖脚本和不稳定的定制逻辑

输出要点：
- 技术风险
- 维护风险
- 改动时需要特别注意的区域

### 5. 形成结论与建议

最终输出应至少包含：
1. 项目概述
2. 关键模块和入口
3. 架构理解
4. 运行/测试方式
5. 风险与注意事项
6. 适合的后续行动

输出风格：
- 先事实、后判断
- 对不确定之处加注“待验证”
- 不做空泛结论，尽量给出可行动的建议

## 决策分支

### 当项目很小/很简单时
- 优先收集：README、入口文件、测试脚本
- 偏向“快速理解 + 最小运行验证”
- 结论通常可在 10–20 分钟内整理完成

### 当项目较大/较复杂时
- 先按“架构层”拆分：应用层、服务层、基础设施层、脚本/工具层
- 只跟踪关键链路，不追求全量阅读
- 把风险分为：高风险、可接受、待确认

### 当项目文档不足时
- 不靠猜测，转而追踪：
  - 启动脚本
  - 测试脚本
  - 依赖声明
  - 核心入口文件
- 先形成“构成事实”，再补充“结构推断”

### 当项目存在多语言或混合架构时
- 先定义“主职责层”：主应用、适配层、底层引擎、脚本层
- 区分“业务代码”和“接口/适配/测试辅助代码”
- 以最靠近最终产物的路径为主线

## 完成标准

可视为一次“好”的项目分析，至少满足：
- 能说清项目是什么
- 能指出关键目录和入口
- 能解释主要模块职责
- 能说明运行和测试方式
- 能识别主要风险与改动注意事项
- 能给出下一步行动建议

## 适用模板

项目分析可按如下结构输出：

```text
1. 项目概述
2. 技术栈与定位
3. 目录与模块分布
4. 核心入口与调用链
5. 运行与测试方法
6. 关键依赖与外部系统
7. 风险清单
8. 建议与后续行动
```

## 例子

适合的提示词：
- “分析这个项目的结构和主要职责”
- “帮我快速理解这个代码库的架构和入口”
- “评估这个项目的运行方式与技术风险”
- “我想接手这个仓库，先给我一个项目分析摘要”
- “从维护角度看，这个项目哪些部分最容易出问题？”

## 说明

本技能是“工作区级项目分析”，适合在当前仓库内使用。它偏向代码库理解和审阅，不是替代详细的功能设计或实施计划。若项目需要进一步落地，后续可以扩展为：
- 架构评审 skill
- 重构风险评估 skill
- 模块定位 skill
- 测试覆盖分析 skill
- 发布/部署评审 skill
